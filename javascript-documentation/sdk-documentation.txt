================================================================================
                    SIGNALHOUSE JAVASCRIPT SDK DOCUMENTATION
================================================================================

INSTALLATION
--------------------------------------------------------------------------------
  npm install @signalhouse-sms/sdk


INITIALIZATION
--------------------------------------------------------------------------------
  import { SignalHouseSDK } from "@signalhouse-sms/sdk";

  const signalHouse = new SignalHouseSDK({
    apiKey: "your-api-token",
    baseUrl: "https://v2.signalhouse.io",
  });

  Required options:
    - apiKey   (string)  JWT token or service user token for authentication
    - baseUrl  (string)  API base URL

  The SDK throws an error at initialization if apiKey or baseUrl is missing.


PER-REQUEST TOKEN OVERRIDE
--------------------------------------------------------------------------------
  Every SDK method accepts an "options" object with a "token" property to
  override the default apiKey for that single request.

  Example:
    const response = await signalHouse.messages.getMessages({
      page: 1,
      limit: 10,
      options: { token: "user-specific-jwt-token" },
    });

  The per-request token takes precedence over the apiKey provided at
  initialization. The original apiKey remains unchanged.


CUSTOM HEADERS
--------------------------------------------------------------------------------
  Pass additional headers via the options.headers property:

  Example:
    const response = await signalHouse.numbers.getPhoneNumbers({
      page: 1,
      limit: 20,
      options: {
        headers: {
          "X-Request-Id": "req_abc123",
        },
      },
    });


IDEMPOTENT REQUESTS
--------------------------------------------------------------------------------
  Pass options.idempotencyKey to make a create, update or delete safe to
  retry. The SDK sends it as the Idempotency-Key header. A retry with the same
  key and the same request replays the first response, marked with the
  response header Idempotent-Replayed: true, instead of running the request
  again.

  - Use a new key (a UUID is recommended) for each new operation, and reuse
    it only to retry that exact request.
  - Keys are scoped to the authenticated user and kept for 24 hours.
  - Reusing a key for a different request returns 422; retrying while the
    first request is still running returns 409 with Retry-After.
  - The SDK never creates a key for you. GET requests ignore it, and the
    Voice service does not support it.

  Example:
    const response = await signalHouse.subgroups.createSubgroup({
      subgroupData: { groupId: "G0000001", subgroupName: "Support" },
      options: { idempotencyKey: crypto.randomUUID() },
    });

AUDIT  (signalHouse.audit.admin — enableAdmin only, staff)
--------------------------------------------------------------------------------
  admin.getAuditEvents({ entityType, entityId, groupId, page, limit })
    GET /audit. Who changed a registration or a message template, and what
    changed, newest first. entityType is "registration" or "template" and is
    required with entityId; name a groupId instead to read a group's events.
    limit defaults to 25, max 100. Returns: { data, total, page, limit };
    each event is { _id, occurredAt, actor { type, userId, role }, entity
    { type, id, groupId }, action, changes [{ path, from, to }] }. Actions:
    CREATE, UPDATE, SUBMIT, LAUNCH_REQUEST, REVIEW, CORRECT, CANCEL, PUBLISH,
    ARCHIVE. signalhouse_* roles only.


AUTH  (signalHouse.auth)
--------------------------------------------------------------------------------
  login({ email, password, deviceToken })
    Login with email and password. Returns { token }, or { mfaRequired: true,
    challengeId, methods, primaryMethod, hasBackupCodes } when 2FA is on, or
    { token, twoFactorSetupRequired: true } (a setup-only session) when the
    user's group requires 2FA and they haven't turned it on.
    deviceToken (from verifyTwoFactorChallenge) skips 2FA on a trusted device.

  resetPassword({ userId, newPassword })
    Reset a user's password.

  getAuthHistory({ groupId, userId, page, limit })
    Get token login history.

  logoutAll()
    Log out all other users in the caller's active group.

  getOAuthProviders()
    List the OAuth sign-in providers enabled on this API.

  getOAuthAuthorizationUrl({ provider, next, email, linkTicket, reauthTicket })
    Build the URL that starts an OAuth sign-in (navigate the browser to it;
    not an API call). next is an optional same-site path that is handed back
    on the /auth/callback redirect. provider "sso" (Enterprise SSO) needs the
    user's work email. A linkTicket (from createOAuthLink) links the provider
    to the signed-in account instead of signing in. A reauthTicket (from
    createOAuthReauth) signs the account in again to confirm it's them; "sso"
    needs no email then.

  getOAuthLinks()
    Your sign-in methods: passwordKnown, and the providers linked to your
    account.

  createOAuthLink({ provider })
    Start linking Google, Microsoft or Apple; returns a 2-minute linkTicket for
    getOAuthAuthorizationUrl. Needs a fresh confirmTwoFactorIdentity.

  createOAuthReauth({ provider })
    Start signing in again with a provider already linked to your account,
    to confirm it's you. Sends a POST to /auth/oauth/:provider/reauth
    ("microsoft", "apple" or "sso"; Google is refused with 400). Returns a 2-minute
    reauthTicket for getOAuthAuthorizationUrl and a reauthSecret to keep for
    confirmOAuthReauth; the browser comes back to
    /Settings/Security with a single-use pendingReauth (the session that
    started it redeems it with confirmOAuthReauth) or reauthError (reauth_wrong_account,
    reauth_unsupported, reauth_stale, invalid_state, sso_not_configured,
    access_denied, provider_error). Spends nothing.

  confirmOAuthReauth({ pendingReauth, reauthSecret })
    Finish signing in again with a linked provider. Sends a POST to
    /auth/oauth/reauth/confirm with { pendingReauth, reauthSecret }. pendingReauth
    is the
    single-use value (valid 5 minutes) the createOAuthReauth round trip returns
    to /Settings/Security with. It counts only for the same account and
    session that started it; 400 when expired or used, 403 for another
    account or session. reauthSecret is the value the create call returned;
    a wrong or missing secret is refused (403) and uses up the re-sign-in.
    Returns: { identityConfirmed } (true when 2FA is off, so it counts as a
    confirmed identity).

  confirmOAuthLink({ pendingLink })
    Finish linking: the provider round trip returns to /Settings/Security
    with ?pendingLink=…; this links it, but only for the account the link
    was started for.

  deleteOAuthLink({ provider })
    Unlink a provider. Refused when it is your only way to sign in. With 2FA on and no password, the last linked Microsoft, Apple or SSO sign-in is refused (400) too. Needs a
    fresh confirmTwoFactorIdentity.

  readOAuthTicket({ ticket })
    Read what an OAuth callback ticket resolves to (session, select or
    signup) without consuming it.

  exchangeOAuthTicket({ ticket, userId, deviceToken })
    Exchange a session/select OAuth ticket for a JWT. userId is required for
    a select ticket. Like login, may return { mfaRequired: true, ... }.

  getTwoFactorSettings()
    Get your 2FA settings: methods (targets masked), default method,
    backup-code counts, trusted devices.

  confirmTwoFactorIdentity({ password, code, method, usingBackupCode })
    Confirm it's you before a sensitive 2FA change (startTwoFactorEnrollment,
    removeTwoFactorMethod, regenerateBackupCodes, disableTwoFactor). Pass a
    code or backup code while 2FA is on, the password while it's off. Lasts
    5 minutes, belongs to the session that made it, unlocks one change.

  sendTwoFactorIdentityCode({ method })
    Send a code by "sms" or "email" for confirmTwoFactorIdentity.

  startTwoFactorEnrollment({ method, phone, address, deviceName })
    Start enrolling "app", "sms" or "email". App returns secret + otpauthUri;
    sms/email send a code. Needs confirmTwoFactorIdentity first.

  confirmTwoFactorEnrollment({ enrollmentId, code })
    Confirm with the code. The first method turns 2FA on and returns backup
    codes (shown once).

  setTwoFactorPrimaryMethod({ method })
    Choose the method offered first at sign-in.

  removeTwoFactorMethod({ method })
    Remove a method. Removing the last one turns 2FA off. Needs
    confirmTwoFactorIdentity first.

  regenerateBackupCodes()
    Replace all backup codes (shown once). Needs confirmTwoFactorIdentity
    first.

  revokeTrustedDevice({ deviceId })
    Stop trusting a device.

  disableTwoFactor()
    Turn 2FA off. Needs confirmTwoFactorIdentity first.

  getTwoFactorPrompt() / dismissTwoFactorPrompt()
    Whether the "secure your account" prompt is due / dismiss it.

  sendTwoFactorChallengeCode({ challengeId, method })
    Send a sign-in code by "sms" or "email".

  verifyTwoFactorChallenge({ challengeId, code, method, usingBackupCode,
                             rememberDevice, deviceName })
    Verify a sign-in code or backup code. Returns { token, deviceToken? }.

  cancelTwoFactorChallenge({ challengeId })
    Cancel a pending sign-in challenge.

  admin.resetUserTwoFactor({ userId })            (enableAdmin, staff only)
    Turn 2FA off for a locked-out user.

BRANDS  (signalHouse.brands)
--------------------------------------------------------------------------------
  getBrands({ id, subgroupId, groupId, page, limit, status, registrationType,
              currentTollFreeCarrier })
    List brands with filters. Staff roles listing all brands (no id/subgroupId/groupId) can also
    pass search, sortBy, sortOrder, entityType, ein, email, referenceId, groupIds, createdFrom,
    createdTo and excludeDeleted; with both page and limit that list returns
    { data, total, page, limit, totalPages }.
    currentTollFreeCarrier: with subgroupId or groupId, true returns only toll-free brands
    that a new toll-free campaign in that group can use.
    A toll-free brand's tollFree.reviewsBusinessOnSubmit says whether it's reviewed when
    it's submitted and keeps its business details from then on. Such a brand also carries
    its tollFree.businessStructure, industry, contactEmail, contactJobTitle and
    contactJobLevel, and tollFree.rejectionReason (why its review rejected it, in plain
    English, or null). On other toll-free brands these are null or absent.

  createBrand({ brandData })
    Create a new 10DLC brand.

  getCallerName({ brandId })
    Get a brand's caller name (CNAM) and the numbers it applies to. Sends a GET to
    /brand/cnam/:brandId. Returns 200: { brandId, companyName, cnamName, eligible,
    numbers: { total, items } }; items lists the first 100 numbers.

  setCallerName({ brandId, name })
    Set a brand's caller name for every number whose caller name comes from the brand, names
    set on a number included; numbers that later come under the brand get it too. The name
    may only remove characters from the brand's registered name (1-15 letters, digits,
    spaces, - and _) and the brand must be verified. Sends a PUT to /brand/cnam/:brandId.

  deleteCallerName({ brandId })
    Remove a brand's caller name. Its numbers fall back to auto-apply, or to no caller name;
    names set on a number are kept. Sends a DELETE to /brand/cnam/:brandId.

  createTollFreeBrand({ brandData })
    Create a new toll-free brand. Sends a POST to /brand/toll-free with brandData as the
    body; the toll-free details go under brandData.tollFree, and the CreateTollFreeBrandData
    typedef lists every field.
    When the group's toll-free brands are reviewed on submit (see getTollFreeRequirements),
    brandData.tollFree also needs businessStructure, industry, contactEmail, contactJobTitle
    and contactJobLevel, tollFree.countryCode must be "US" or "CA", and state must be a
    2-letter state or province code. Any other group gets 400 if it sends any of those five.
    businessStructure: CO_OPERATIVE, CORPORATION, LIMITED_LIABILITY_CORPORATION,
    NON_PROFIT_CORPORATION or PARTNERSHIP. contactJobLevel: DIRECTOR, GM, VP, CEO, CFO,
    GENERAL_COUNSEL or OTHER. The TollFreeBrandDetails typedef lists the industry values.
    Such a brand stays DCA_PENDING until it's reviewed, which usually takes 1–2 business
    days, then becomes DCA_ACTIVE, or DCA_REJECTED with tollFree.rejectionReason saying why.
    Its business details can't be changed after it's submitted: companyName, street, city,
    state, postalCode, country, firstName, lastName and tollFree's businessRegistrationType,
    taxId, countryCode, taxIdIssuingCountry, businessStructure, industry, contactEmail,
    contactJobTitle and contactJobLevel. A rejected brand is fixed by creating it again with
    the corrections.
    Returns 202: the new brand, with status PENDING_CREATION.

  getTollFreeRequirements({ groupId })
    Get whether a group's new toll-free brands are reviewed when they're submitted, which
    decides the details createTollFreeBrand needs. Sends a GET to
    /brand/toll-free-requirements/:groupId.
    Returns 200: { groupId, reviewsBusinessOnSubmit }. When reviewsBusinessOnSubmit is true,
    a new toll-free brand needs tollFree.businessStructure, industry, contactEmail,
    contactJobTitle and contactJobLevel, a tollFree.countryCode of "US" or "CA" and a
    2-letter state or province code; it stays DCA_PENDING until it's reviewed, and its
    business details can't be changed after it's submitted. When it's false, those five
    fields are refused.
    Returns 403 when the caller can't view the group.

  updateBrand({ brandId, brandData })
    Update brand information.

  deleteBrand({ brandId })
    Delete (soft) a brand.

  transferBrand({ subgroupId, brandIds })
    Transfer brands to a different subgroup.

  getExternalVetting({ brandId })
    Get external vetting info for a brand.

  createExternalVetting({ brandId })
    Submit brand for external vetting.

  revetBrand({ brandId })
    Resubmit brand for vetting.

  getAppealHistory({ brandId })
    List identity status appeals for a brand.

  submitAppeal({ brandId, appealCategories, explanation, file })
    Submit a brand identity status appeal with supporting documentation.
    Uses multipart/form-data automatically.
    appealCategories: array of strings (VERIFY_TAX_ID, VERIFY_NON_PROFIT, VERIFY_GOVERNMENT)
    explanation: string (max 1024 chars)
    file: binary (supported: .jpg, .jpeg, .png, .bmp, .raw, .tiff, .pdf, .docx, .htm, .odt, .rtf, .txt, .xml)

DNC  (signalHouse.dnc.admin — enableAdmin only)
--------------------------------------------------------------------------------
  The attested "Disable Automated Opt-Out" setting is signed inside a
  Signal House app (the portal, or the GHL / Shopify apps running as
  signalhouse_api), not by API consumers, so every method lives under the
  admin namespace. The API refuses the customer "api" (API key) role.

  admin.getCurrentAttestation({ groupId })
    Current Opt-Out Handling Attestation text with the account placeholders
    filled, plus the version and templateSha256 a signature must echo back.
  admin.signAttestation({ version, templateSha256, checkboxAcknowledged,
                          scrolledToEnd, customerLegalName, signerName,
                          signerTitle, groupId, signerEmail, signerUserId,
                          signedVia, signerIpAddress, signerUserAgent })
    E-sign. A portal login signs its own account (identity from the
    session). A signalhouse_api app passes groupId plus the signer it
    authenticated (signerEmail required; signedVia e.g. "ghl", "shopify").
  admin.revokeAttestation({ groupId })
    Revoke the active attestation and re-enable automated opt-out.
    groupId is for signalhouse_api apps.
  admin.getAttestation({ groupId })
    Attestation state: automatedOptOutDisabled, active record, history,
    requiresResign, resignDeadline.
  admin.listAttestations({ status, groupId, page, limit })   (staff)
  admin.getAttestationById({ id })                            (staff)
  admin.revokeAttestationById({ id, reasonCode, reason })     (staff)

TEMPLATES  (signalHouse.templates)
--------------------------------------------------------------------------------
  Channel-generic templates under /template (today the only channel is
  "rcs"). Each template has an immutable published version and at most one
  editable draft. Every call takes groupId. Writes apply directly (last write
  wins); 409 codes are TEMPLATE_ARCHIVED, TEMPLATE_NAME_TAKEN, NO_DRAFT
  (publish with no draft) and DRAFT_CHANGED (publish only: the draft changed
  while it was being published; publish again). 404 while RCS is disabled
  for the environment. Bodies are the raw
  RcsTemplateBody { channel: "rcs", contentFormat?, content, variables,
  defaults, fallback }; the SDK never converts them. contentFormat defaults to
  "content.v1" (content: { blocks }, the only format the API stores and
  returns); "google.rcs" sends Google's RBM AgentContentMessage as content,
  which the API converts to content.v1. A VIEW_LOCATION suggestion takes
  latitude/longitude or an address the API geocodes.
  version selectors are a positive integer, "draft" or "published"; omitted
  means the published version, else the draft.

  create({ groupId, name, tag, body })
    Create a template with draft version 1 (201). Returns { head, version, validation }. validation is
    { valid, errors, warnings }, null when the checks could not run; update returns it too, and publish returns
    { head, version, warnings }. A draft saves even when validation lists errors. On an RCS send, a blocked row
    carries blockReason, reason and issues.
    Required: groupId, name, body

  list({ groupId, state, channel, tag, search, sortBy,
         sortOrder, page, limit })
    List templates. state: DRAFT | PUBLISHED | ARCHIVED; sortBy: name |
    createdAt | updatedAt. Returns { data, total, page, limit }.

  get({ templateId, groupId, version })
    Get a template head with one version. Returns { head, version }.

  update({ templateId, groupId, name, tag, body })
    Rename, retag or replace the draft body. tag: null clears it, omitted
    leaves it unchanged.

  publish({ templateId, groupId })
    Publish the current draft. No draft returns 409 NO_DRAFT; a draft changed
    mid-publish returns 409 DRAFT_CHANGED (publish again); an incomplete
    draft returns 400 TEMPLATE_INVALID with { errors, warnings }.
    Publish and validate send each block's text and images to the Moderation
    API. A flag is an error { severity: "error", code:
    "CONTENT_POLICY_FLAGGED", path, message, blockId } whose message names the
    category, for example "Content moderation flagged this text: spam". The
    check passes when the Moderation API fails, and saving a draft does not
    run it.

  archive({ templateId, groupId })
    Archive a template. Returns the template head.

  versions({ templateId, groupId, page, limit })
    List versions without bodies. Returns { data, total, page, limit }.

  validate({ templateId, groupId, body, version })
    Validate an unsaved body or a stored version; writes nothing. Pass exactly
    one of body or version (the SDK throws otherwise). Returns { valid,
    contentHash, validatorVersion, errors, warnings }. errors include
    CONTENT_POLICY_FLAGGED, as on publish.

  capabilities({ groupId, channel, provider })
    Allowed blocks, actions, variable types, limits, accepted contentFormats,
    whether geocoding is available, upload constraints, time to live ranges
    (ttlPresets), traffic types per use case and iPhone layout numbers (ios).
    provider (infobip | sinch) adds that provider's limits and unsupported features.

  geocodeAddress({ groupId, address })
    Resolve an address to { address, latitude, longitude, partialMatch } for a
    VIEW_LOCATION suggestion. 400 LOCATION_NOT_FOUND when nothing matches; 429
    past the group's lookup window; 503 when the server has no geocoding provider.
    Required: groupId, address

  uploadMedia({ groupId, file, fileName })
    Upload a Blob/File; returns { mediaId, url, bytes, mimeType, kind, width,
    height, ... } (201). Use url in a template body. 503 when media storage is
    not configured. Uses multipart/form-data automatically.
    Required: groupId, file

  Pass options.idempotencyKey on create, update, publish, archive and
  uploadMedia to make a retry safe (see IDEMPOTENT REQUESTS).


RCS AGENTS  (signalHouse.rcs.agents)
--------------------------------------------------------------------------------
  RCS agents under /rcs/agent. An agent links one brand and one campaign, of
  any registration type: the campaign's numbers are its SMS fallback, and the brand and
  campaign supply the company identity and consent text for the carrier
  launch. One brand or campaign can serve many agents. An agent is a
  registration (type RCS_AGENT, agentId = registrationId "RCSA" + 10
  characters). 404 while RCS is disabled for the environment; 400 while the
  group's rcsEnabled flag is off. To use a new brand and campaign, create the
  brand (brands.createBrand), wait until it is VERIFIED, create the campaign
  (campaigns.createCampaign), then link them.

  The agent: { agentId, groupId, subgroupId, status, registrationStatus,
  stage, brandId, brandRef, campaignId, campaignRef, links, agent, consent,
  useCase, billingCategory, defaultFallback, excludedCarriers, testers,
  contact, testerInvites, carriers, carrierUpdate, autofill, launchable, review, redlineDiff, submittedAt,
  approvedAt, history, createdAt, updatedAt }. launchable is true
  when the launch request would be accepted now. brandRef and
  campaignRef are the linked records' _ids; brandId and campaignId are their
  current public ids (brandId is null until TCR assigns one). links = {
  brand: { state: OK | NOT_VERIFIED | MISSING, ... }, campaign: { state: OK |
  NOT_ACTIVE | MISSING | NONE, ... } }; a deleted brand or campaign reads
  MISSING. status: DRAFT, PENDING_REVIEW, REJECTED, AGENT_CREATING (approved,
  waiting for the carrier launch), ARCHIVE_PENDING (waiting for the carrier partner
  to cancel it), ARCHIVED.

  carrierUpdate is null, or { status: REQUESTED | SENT, carriers, requestedAt,
  requestedBy, sentAt, sentBy }: the corrected launch answers the customer sent
  to Signal House after a carrier rejected a launch other carriers took (status
  PARTIALLY_LAUNCHED with a REJECTED carrier). In that state an update may
  change only consent and contact, nothing is pushed to the carrier partner, and
  requestCarrierUpdate sends the update to Signal House, which emails it to the
  carrier partner. autofill holds one marker per prefilled field, keyed by its
  path (consent.optInDetails): { source: brand | campaign | landing, sourceId,
  at, edited }. The API marks the fields it fills from the campaign or the
  brand's landing page; send autofill on create or update for the fields you
  prefilled. Omitted on update, the stored markers stay, and a marker turns
  edited once its field changes.

  create({ brandId, campaignId, agent, consent, contact, useCase, billingCategory,
           defaultFallback, excludedCarriers, testers, autofill })
    Create a draft (201). brandId is a carrier brand ID, provisional UUID or
    _id; campaignId (optional until submit) is a campaign ID or _id of that
    brand. The agent's subgroup is the brand's. Blank consent fields fill
    from the campaign. Required: brandId

  list({ groupId, subgroupId, status, brandId, campaignId, page, limit })
    List agents, newest first. brandId / campaignId return the agents linked
    to that brand or campaign. Returns { data, total, page, limit }.

  get({ agentId })
    One agent with the live state of its links. googleAgentId is Google's id
    for the agent, null until Google has created it.

  update({ agentId, brandId, campaignId, agent, consent, contact, useCase,
           billingCategory, defaultFallback, excludedCarriers, testers, autofill })
    Edit an agent while it may change (DRAFT, REJECTED, ACTION_REQUIRED,
    CARRIER_REJECTED, or IN_TESTING, whose change is pushed to the carrier
    partner). agent, consent and contact merge field by field; other keys
    replace; campaignId: null unlinks. 409 in any other status; brandId is
    locked once the agent exists at the partner, billingCategory once a launch
    was requested. contact is { firstName, lastName, role, email, mobile }, the
    individual the partner's reviewers may write to (needed at launch).

  validate({ agentId })
    Returns { valid, errors, warnings } of { field, reason } for the next gate:
    what creating the agent needs, or, once it exists, what the launch needs.
    Writes nothing.

  submit({ agentId })
    Create the agent at the carrier partner, with no review first. Needs the
    full profile, useCase and a billingCategory; otherwise 400 with
    details { code: "REGISTRATION_INCOMPLETE", errors, warnings }. The agent
    moves to AGENT_CREATING, then IN_TESTING once the partner reports it ready.
    A group that has not finished account verification gets 403 with code
    GROUP_UNVERIFIED, and a rejected group 403 with code GROUP_REJECTED; a
    pending verification passes.

  launch({ agentId, acknowledgeFees, acknowledgePhi })
    Request the launch (POST /registration/:agentId/launch). The launch
    requirements are checked (a VERIFIED brand, the campaign, the full consent
    with the launch video, the contact) and the agent goes to PENDING_REVIEW;
    Signal House's approval files the launch with the carrier partner. Allowed
    from IN_TESTING, REJECTED and CARRIER_REJECTED (409 otherwise); a failed
    requirement is 400 REGISTRATION_INCOMPLETE.
    The launch text must also pass the carriers' copy rules. Each failure is an
    error whose code is the carrier partner's key:
    OPT_IN_MSG_BRAND_NAME_MISSING, OPT_IN_MSG_FREQ_DISCL_MISSING,
    OPT_IN_MSG_HELP_INSTR_MISSING, OPT_IN_MSG_RATE_DISCL_MISSING,
    REG_BRAND_IN_OPT_IN_CONF_MESSAGE_MISSING, HELP_BRAND_NAME_MISSING,
    HELP_SUPP_CONTACT_MISSING, OPT_OUT_BRAND_NAME_MISSING,
    OPT_OUT_NO_CESSATION_CONF, SAMPLE_MSG_BRAND_NAME_MISSING,
    SAMPLE_RATE_DISCL_MISSING, SAMPLE_HAS_PUBLIC_URL_SHORTENER. The brand-name
    rules look for the brand's display name. 403 GROUP_UNVERIFIED and
    GROUP_REJECTED as on submit.
    When any fee is due the request needs acknowledgeFees: true, or it gets a 400
    with code FEE_ACKNOWLEDGEMENT_REQUIRED and nothing is held.
    The request charges the agent's launch fees: a wallet that cannot cover
    them gets a 402, and the agent stays where it is.
    The agent's launchFees quotes what the next request charges.
    When the agent's brand vertical is healthcare or insurance, the launch
    needs the protected health information (PHI) disclosure acknowledged:
    send acknowledgePhi: true, or the request gets a 400
    REGISTRATION_INCOMPLETE whose errors name consent.phiAcknowledgement. The
    API records the acknowledgement as consent.phiAcknowledgement
    { acknowledgedAt, acknowledgedBy } from the caller; the client sends only
    the boolean, and an agent update cannot set it. Once recorded, a later
    launch request needs no new acknowledgement.

  requestCarrierUpdate({ agentId })
    POST /registration/:agentId/carrier-update. Send Signal House the corrected
    launch answers after a carrier rejected a launch other carriers took; edit
    consent and contact first. Returns the agent's registration with
    data.carrierUpdate REQUESTED for the rejected carriers; it reads SENT once
    Signal House sent it. 409 when no carrier is REJECTED after a partial
    launch, or an update already waits.

  archive({ agentId })
    Archive the agent.
    One the carrier partner created stops sending at once and stays ARCHIVE_PENDING until
    Signal House confirms the partner cancelled it, then ARCHIVED. Archiving cannot be undone;
    an agent already ARCHIVE_PENDING answers 409.

  resendTesterInvite({ agentId, phoneNumber })
    POST /rcs/agent/:agentId/testers/:phoneNumber/resend. Resend a tester's expired invitation.
  removeTester({ agentId, phoneNumber })
    DELETE /rcs/agent/:agentId/testers/:phoneNumber. Remove a tester at once, at any point before the agent is archived.

  createEntryPoints({ agentId, body })
    POST /rcs/agent/:agentId/entry-points. Make the links that start a chat
    with the agent: an sms: deep link in Google's format, and a short link
    that redirects to it, for a QR code. With the agent's
    defaultFallback.from, the deep link names that number, so a handset that
    cannot reach the agent texts it. body (optional, max 1,000 characters) is
    the message the chat opens with. The same request returns the same short
    link. The links reach approved testers until a carrier launches the agent.
    409 with code GOOGLE_AGENT_PENDING before Google has created the agent.
    Required: agentId
    Returns: { googleAgentId, deepLink, shortLink }

  uploadAsset({ agentId, kind, file, fileName })
    Host a logo (224 x 224 px, 50 KB max) or hero (1440 x 448 px, 200 KB max)
    PNG or JPEG and set it on the draft. kind: logo | hero. Uses
    multipart/form-data automatically. Required: agentId, kind, file

  Pass options.idempotencyKey on create, update, submit, launch, archive and
  uploadAsset to make a retry safe (see IDEMPOTENT REQUESTS).


RCS MESSAGES  (signalHouse.rcs.messages)
--------------------------------------------------------------------------------
  Send through an agent. 404 while RCS is off for the environment, 403 while
  the group's rcsEnabled flag is off, 409 while the agent cannot send yet.

  send({ agentId, recipients, templateId, templateVersion, content,
         contentFormat, trafficType, ttlSeconds, expireTime, fallback,
         statusCallbackUrl, enableShortlink, isTest, simulate })
    POST /message/rcs. Send to up to 100 recipients. A blocked recipient gets a
    BLOCKED message and the rest still send. Exactly one of templateId or
    content; at most one of ttlSeconds or expireTime. contentFormat: content.v1
    (default) | google.rcs. recipients is an array of { phoneNumber, variables,
    clientMessageId, metadata }. fallback is { mode (auto, rcs_only, sms_only),
    channel (auto, sms, mms), from, content: { text, mediaUrls },
    validitySeconds }; without content the template's fallback, else a
    generated one, is used. simulate: not_capable | ttl_expired | delivered |
    read, approved testers only. Required: agentId, recipients
    Returns: { requested, enqueued, failed, bulkId, messages } (201)
    A recipient from 19999990000 to 19999990359 makes the whole request a
    simulation, as on SMS: it returns { simulated: true, webhooks } and nothing
    is stored, sent or charged.

  sendBatch({ ...the send parameters })
    POST /message/rcs/batch. Send to up to 10,000 recipients in the
    background. The request runs the send's request checks, splits the
    recipients into chunks of 100, queues each chunk and answers 202. Every
    message carries the shared bulkId; track progress with the messages list
    filtered by bulkId (GET /message?bulkId=) and per-message webhooks. A chunk
    the wallet cannot cover, or that is refused after acceptance, gets BLOCKED
    messages with blockReason INSUFFICIENT_FUNDS or SEND_REFUSED; a chunk that
    keeps failing gets SEND_FAILED. Send an Idempotency-Key to make a retry
    safe (same bulkId, no duplicate sends); a retry without one may send
    duplicates. Required: agentId, recipients
    Returns: { bulkId, status: "ACCEPTED", recipientCount } (202)

  validate({ ...the send parameters })
    POST /message/rcs/validate. Check a send; writes nothing.
    Required: agentId, recipients
    Returns: { valid, errors, warnings, billingClass, segments,
    estimatedCostMicros, unsupportedFiles, recipients }. It runs a send's
    checks and holds no funds. valid is true only with no errors.

  estimate({ agentId, recipients, recipientCount, templateId, templateVersion,
             content, contentFormat, trafficType, ttlSeconds, expireTime,
             fallback })
    POST /message/estimate with channel "rcs" added. Price a draft in
    microdollars; no charge or send. Exactly one of recipients or
    recipientCount. fallback.from is optional here: with none, the fallback
    leg is priced on the channel of the agent's linked campaign.
    Required: agentId
    Returns: { billingClass, segments, recipientCount, rcsLeg, fallbackLeg,
    totals, balance, issues, warnings }
    rcsLeg.mediaSurcharge is the carrier's surcharge on media over 5 MB for one recipient, and rcsLeg.cost already holds it for every recipient; rcsLeg.cost is null with the fallback mode sms_only; a message over 100 MB adds a MEDIA_TOO_LARGE
    issue.

  capabilities({ agentId, phoneNumbers })
    POST /rcs/capabilities. Report which numbers (up to 500) can receive RCS.
    Required: agentId, phoneNumbers
    Returns: { results: [{ phoneNumber, capability, rcsEnabled, reason, features,
    carrier, checkedAt, cached }] }. capability is ENABLED, UNREACHABLE or
    UNKNOWN; reason is CAPABLE, NOT_CAPABLE, NOT_LAUNCHED_ON_CARRIER or UNKNOWN.
    rcsEnabled is true only for CAPABLE. carrier and checkedAt may be null, and
    features is empty today.

  simulateInbound({ agentId, from, type, text, postbackData, messageId, buttonId,
                    latitude, longitude, fileName })
    POST /message/rcs/simulate-inbound. Fake an inbound event from an approved
    tester, with no carrier involved. It runs the real handlers and webhooks as
    free test traffic; a simulated STOP really opts the tester out.
    type: TEXT, SUGGESTION, LOCATION, FILE or UNSUBSCRIBE. TEXT needs text;
    SUGGESTION needs the postback or button; LOCATION needs both coordinates.
    Anyone else gets a 403 with code NOT_TESTER.
    Returns: { status: "QUEUED", messageId }

  get({ messageId })
    GET /message/:messageId. Get one message; the same route as
    messages.getMessage. A settled RCS message carries carrierFeeMicros, the
    carrier pass-through and media surcharge it was charged. Required: messageId

  list({ groupId, from, to, agentId, status, page, limit, templateId,
         templateVersion, bulkId, fallbackReason, billingClass,
         deliveredChannel, isTest })
    GET /message with messageType=RCS. agentId is sent as registrationId, from
    as startDate and to as endDate. Required: groupId, from, to

  Pass options.idempotencyKey on send and sendBatch to make a retry safe (see
  IDEMPOTENT REQUESTS).

================================================================================
                          MULTIPART REQUESTS
================================================================================

  The following methods use multipart/form-data automatically:

    - messages.sendMMS(...)
    - messages.sendGroupMessage(...)
    - landings.createLanding(...)
    - landings.updateLanding(...)
    - brands.submitAppeal(...)
    - templates.uploadMedia(...)

  You do not need to construct FormData manually. Pass parameters as a normal
  object and the SDK builds the form data internally.


================================================================================
                          QUERY STRING HELPERS
================================================================================

  The SDK automatically constructs query strings from method parameters.
  Any parameter with an undefined value is excluded, so you only need to
  pass the filters you care about.

  Example:
    // Only sends ?status=FAILED&page=1&limit=50
    const messages = await signalHouse.messages.getMessages({
      status: "FAILED",
      groupId: undefined,   // excluded
      direction: undefined, // excluded
      page: 1,
      limit: 50,
    });


================================================================================
                             VALIDATION
================================================================================

  The SDK validates required parameters client-side before making any HTTP
  request. If a required parameter is missing, null, or an empty string,
  the SDK throws a SignalHouseValidationError immediately -- no network
  request is made.

  Validation errors have:
    - name:    "SignalHouseValidationError"
    - message: "Missing required parameter: <fieldName>"
    - status:  400


================================================================================
                           ERROR HANDLING
================================================================================

  The SDK uses a standardized response format. Errors are NOT thrown --
  they are returned as response objects with success: false.

  Success response:
    { success: true, data: { ... }, status: 200 }

  Error response:
    { success: false, error: "Error message", status: 400 }

  Error types summary:

    Source                    Behavior                         How to Handle
    -----------------------------------------------------------------------
    Missing required param    Throws SignalHouseValidationError try/catch
    HTTP 4xx/5xx from API     Returns { success: false, ... }  Check response.success
    Network failure           Returns { success: false, ... }  Check response.success


================================================================================
                       COMPLETE INTEGRATION EXAMPLE
================================================================================

  import express from "express";
  import { SignalHouseSDK } from "@signalhouse-sms/sdk";

  const app = express();
  app.use(express.json());

  const signalHouse = new SignalHouseSDK({
    apiKey: process.env.SIGNALHOUSE_API_KEY,
    baseUrl: "https://v2.signalhouse.io",
  });

  // Send an SMS notification
  app.post("/api/notify", async (req, res) => {
    const { recipientNumber, message, senderNumber } = req.body;

    try {
      const response = await signalHouse.messages.sendSMS({
        senderPhoneNumber: senderNumber,
        recipientPhoneNumbers: [recipientNumber],
        messageBody: message,
        statusCallbackUrl: `${process.env.BASE_URL}/api/delivery-status`,
      });

      if (!response.success) {
        return res.status(response.status || 500).json({ error: response.error });
      }

      return res.json({
        messageId: response.data.messageId,
        status: response.data.status,
      });
    } catch (error) {
      if (error.name === "SignalHouseValidationError") {
        return res.status(400).json({ error: error.message });
      }
      return res.status(500).json({ error: "Internal server error" });
    }
  });

  // Receive delivery status callbacks
  app.post("/api/delivery-status", (req, res) => {
    const { messageId, status } = req.body;
    console.log(`Message ${messageId} status: ${status}`);
    res.status(200).json({ received: true });
  });

  // List phone numbers with per-request token override
  app.get("/api/numbers", async (req, res) => {
    const userToken = req.headers.authorization?.replace("Bearer ", "");

    const response = await signalHouse.numbers.getPhoneNumbers({
      page: parseInt(req.query.page) || 1,
      limit: parseInt(req.query.limit) || 20,
      options: { token: userToken },
    });

    if (!response.success) {
      return res.status(response.status || 500).json({ error: response.error });
    }

    return res.json(response.data);
  });

  // Get message analytics
  app.get("/api/analytics", async (req, res) => {
    const { startDate, endDate, campaignId } = req.query;

    const response = await signalHouse.messages.getAnalytics({
      startDate,
      endDate,
      campaignId,
    });

    if (!response.success) {
      return res.status(response.status || 500).json({ error: response.error });
    }

    return res.json(response.data);
  });

  app.listen(3000, () => {
    console.log("Server running on port 3000");
  });


REGISTRATIONS AND REGIONAL REPORTING
--------------------------------------------------------------------------------
signalHouse.registrations is one namespace for every country and every registration
type. type selects the shape of data on a submission and on the record; the catalog
tells you what a region offers. region (never country) is the jurisdiction: US, GB or
CA, and any case of UK/GB/GBR/United Kingdom is accepted for GB.

getCatalog({ region }) calls GET /registration/catalog and returns { region,
jurisdiction, sendingRequiresRegistration, registeredThrough, provisioning, types: [ { type, kind,
channel, provider, bundles, quantity: { min, max }, requiresParent, available } ] }.
registeredThrough is "registration" (use this API), "brandsAndCampaigns" (the US:
register through the Brands and Campaigns APIs) or null (nothing to register, e.g.
Canada). An unlisted country requires registration and offers no types.
Types: TEN_DLC_BRAND, TEN_DLC_CAMPAIGN, TOLL_FREE_BRAND, TOLL_FREE_CAMPAIGN,
SHORT_CODE_BRAND, SHORT_CODE_PROGRAM and SHORT_CODE_LEASE (not available), VIRTUAL_LONG_CODE (UK) and ALPHANUMERIC_SENDER_ID (UK). Kinds: identity, program, sender. Channels: tenDLC, tollFree, shortCode,
virtualLongCode, alphanumeric. Only a type with available: true can be quoted or
submitted; the others return 400.

getQuotes({ region, type, quantity, groupId }) calls GET /registration/quotes (quantity
1-100, default 1; staff may add groupId) and returns { data: [ { capabilities, quantity,
currency, setupAmount, monthlyAmount, totalSetupAmount, totalMonthlyAmount, etaDays } ] }:
one quote per bundle. Amounts are integer microdollars; setupAmount and monthlyAmount
are per number, the totals are for the quantity. There is no quote version to pass back.

createRegistration({ region, type, subgroupId, capabilities, data })
calls POST /registration and returns the registration (201). capabilities is one of the
type's bundles; pass options.idempotencyKey to make a retry safe (see IDEMPOTENT
REQUESTS). data is the type's submission shape. Worked example, the UK
Virtual Long Code (region "GB", type "VIRTUAL_LONG_CODE", capabilities ["SMS"] or
["SMS","VOICE"]): data = { quantity (1-100), useCases (1-10 descriptions), voice }.
voice is required exactly when capabilities include VOICE and is the carrier's voice
dossier: companyName, companyPhone, companyWebsite, companyEmail,

getMessages, getAnalytics, getAnalyticsDetail, getAnalyticsBySubgroup,
getAnalyticsByErrorCode, getDncAnalytics and getDncRecords accept region and regionScopes;
getAnalyticsFilterOptions accepts region. region is US, GB or CA (any case of UK/GB/GBR/United Kingdom is accepted for GB):
one value, an array, or a comma-separated string; omitted means every region. regionScopes
is an array of OR-ed branches, each { region, channels, brandId?, campaignId?,
phoneNumber? } with channels among tenDLC, virtualLongCode, tollFree, shortCode and p2p;
the SDK sends it as JSON. Example:
[{ region: "US", channels: ["tenDLC"], brandId: ["BUS1"] },
 { region: "GB", channels: ["virtualLongCode"], phoneNumber: ["447400123456"] }]
Group authorization and the subgroup/carrier/date filters apply outside the OR. [] matches
nothing; omitting regionScopes keeps the existing filtering. getMessages always accepts
both, as do the analytics and DNC methods.

getAnalytics, getAnalyticsDetail, getAnalyticsThroughput and getDncAnalytics accept
registrationId (one id or an array, sent as repeated query keys like campaignId): filter
to traffic attributed to these registrations. Except on getAnalyticsThroughput, which has no phoneNumber filter, a
phoneNumber filter takes precedence. getPhoneNumbers accepts a single registrationId to
list the numbers provisioned under that registration.

getAnalyticsBySubgroup, getAnalyticsByErrorCode and getDncRecords accept registrationId
the same way, with the same precedence. getMessages accepts
registrationId: it filters to messages attributed to those
registrations, and a phoneNumber filter narrows further. Every method returns 400 when
registrationId is combined with campaignId.

getAnalyticsFilterOptions returns each phone number with its type (TOLL_FREE,
SHORT_CODE, ALPHANUMERIC, VIRTUAL_LONG_NUMBER, and older local-number spellings) and
country (ISO-2), null when unknown. TOLL_FREE, SHORT_CODE and ALPHANUMERIC are channels
by type; a US number of any other type is 10DLC and a non-US one is a Virtual Long Code.
It also returns carriers, a plain array of carrier name strings.

UK sending is SMS only, from a +44 Virtual Long Code to GB mobiles; MMS and group MMS are
unavailable. estimateMessage accepts 10-15 digit recipients; a +44 sender estimates SMS to
GB mobiles only and returns region "GB", and is refused with 400 while UK sending is
disabled for the environment. Amounts are integer microdollars. A READY alphanumeric
sender ID (e.g. "ACME") also sends SMS to UK recipients only; its estimate includes the
opt-out footer.
